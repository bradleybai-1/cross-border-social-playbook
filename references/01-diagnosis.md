# 诊断章写作法（第一章 1.1–1.9）

> 诊断是整份方案的支点。诊断写虚了，后面规划再漂亮也是空转。
> 这一章占全文约 25%，但决定客户信不信你。

---

## 前置：账号数据从哪来

诊断断不能靠猜。开工前先确认数据来源，只有三种合法来源：

| 来源 | 怎么用 |
|---|---|
| **用户提供的截图** | 直接读图。读不清的写「截图未包含」，**不要估** |
| **用户文字告知** | 直接引用，注明「据客户告知」 |
| **公开页面核验** | 可以补充，但必须给链接或说明核验方式 |

**读图时逐项确认这几项**（每个平台都要）：粉丝数、关注数、帖子/视频数、简介原文、用户名（handle）、头像是否可辨识、封面图内容、每条内容的播放/点赞数（逐条列出）、分类或类目。

**读不到的、模糊的、被截断的，一律写「截图未包含」。** 一个编造的粉丝数会让懂行的买家当场否定整份方案。

### 读图精度：三档，不要只分「读到 / 没读到」

「有出处」不等于「读得准」。截图 OCR 最常见的错误不是读不到，是**多读或漏读一位数字**（37 → 137、144 → 44）。三种情况写法不同：

| 读取质量 | 怎么写 | 例子 |
|---|---|---|
| 清晰可读 | 直接写数字，并在附录列出原始读数 | 粉丝 37 |
| 模糊但能判断量级 | 写「约 X」，**不写带零头的精确值** | 约 40（不写「37」或「137」） |
| 无法判断 | 写「截图未包含」 | 收藏数截图未包含 |

**为什么要管这么细：** 同一个账号，粉丝 37 时结论是「129 条内容只换 37 个关注，严重断层」；粉丝 137 时结论变成「接近及格」。**一个数字读错，整份诊断的方向就反过来。**

### 写进结论前，关键数字必须单列核对

凡是要用来**算比率、判等级、支撑核心结论**的数字（粉丝数、帖子数、单条播放量、互动量），在写进正文前先单列一段给用户：

```
请核对以下原始读数（我从截图读到的）：
- 粉丝数：37
- 关注数：8
- 帖子数：129
- 单条播放：110 / 37 / 146 / 169 / 120 / 144 / 118 / 144 / 219
如果有哪个读错了，告诉我改过来再往下写。
```

特别是小数（37、8、44）最容易被读成三位数。**主动请人核对一次，比事后被发现读错一次便宜得多。**

## 1.1 客户与产品概况

用表格，字段固定：

`公司 | 行业 | 产品线 | 产品去向 | 客户类型 | 当前诉求 | 已开平台`

**多产品线的客户，必须再补一张买家分层表**：

| 产品线 | 谁买 | 他关心什么 | 内容该拍什么 |
|---|---|---|---|

然后给一句首期聚焦建议：「首期建议 {X}% 内容聚焦 {A}+{B}，{Y}% 给 {C}」，并给理由（截图已跑出数据的方向优先 / 该品类买家在社媒搜索与停留更强）。

> 为什么必须做这一步：多条产品线「混着发」是 B2B 账号内容混乱最常见的根因。不聚焦，等于每条内容都在跟自己的其他内容抢注意力。

---

## 1.2 账号体检表

每个平台一张表，行固定：

| 体检项 | 实测现状 | 判定 |
|---|---|---|
| 粉丝 / 关注 | | 🟢🟡🔴 |
| 简介 | | |
| 分类 | | |
| 头像 | | |
| 封面图 | | |
| 帖子 / 视频数量 | | |
| 单条播放（逐条列出） | | |
| 合计播放 | | |
| 互动率 | 赞 ÷ 播放 = {X}% | |
| 用户名（handle） | | 🟢🟡🔴 |

**判定语言**：🟢 正确 / 🟡 有但不合格 / 🔴 零起点或致命问题。
每行判定必须一句话说明**为什么**，例：「🔴 手机端缩小后中文看不清、英文买家读不懂」。

### 体检后必须做「数据放在一起读」的解读

4 条，每条给一个结论，不能只列数字：

| 解读角度 | 怎么算 | 结论怎么说 |
|---|---|---|
| **头部集中度** | 最高一条 ÷ 总播放 | > 80% 记为严重头部集中 → 说明只有一次偶然命中推荐池，不是可复制的结构 |
| **中位数播放** | 全部条目的中位数 | 个位数或两位数 = 从未进入推荐池；三位数 = 已进池但不稳定 |
| **粉丝转化** | 总播放 → 粉丝数 | X 播放换来 Y 粉丝 → 流量与关注之间是断的 |
| **流量与询盘** | 是否可追踪询盘 | 0 条可追踪询盘 → 播放与询盘之间是断的 |

> 这四条是诊断里最能立信的部分。客户自己看后台看不出来，你把这三行摆出来，他就知道你是干过活的。

### 变体：C 端 / 收藏型账号的体检表

当产品卖给个人消费者（收藏者、玩家、学生、终端用户）而不是采购经理时，上表的「互动率 = 赞 ÷ 播放」说明不了问题。换成这张：

| 体检项 | 实测现状 | 判定 |
|---|---|---|
| 粉丝 / 关注 | | 🟢🟡🔴 |
| 帖子数 vs 粉丝数 | 帖子 {X} ÷ 粉丝 {Y} = 每条换 {Z} 个关注 | |
| 简介（身份 + 产品 + 型号 + CTA + 免责） | | |
| 用户名（handle） | 是否含品类词，能否被搜索命中 | |
| 头像 / 内容网格视觉一致性 | 有无统一句式与色彩 | |
| 单条播放（逐条列出） | | |
| **收藏 / 保存数** | 比点赞重要 —— 收藏 =「我以后要买」 | |
| **外链点击** | 唯一的硬意向指标 | |
| 每条是否有 CTA | 有没有可做的下一步 | |
| UGC / 社群痕迹 | 有没有用户返图、标签扩散 | |
| 第三方品牌免责声明 | 适配他人产品时必查 | |

**C 端三个必算数（比互动率有用得多）**

1. **粉丝转化率 = 粉丝数 ÷ 帖子数** —— 低于 1 说明内容发了但没人愿意留下。这是诊断「有产量没留存」最直接的一个数。
2. **关注数** —— 个位数等于不在社群里。C 端社群靠互相关注、互相评论运转，只发不看的账号在圈子里等于不存在。
3. **收藏 ÷ 播放** —— 购物意图的代理指标，比点赞可信得多。

> 三个数一摆，客户自己看后台看不出来的问题就露出了。这比「互动率 3.2%」有说服力。

## 1.3 已经做对的部分（不能省）

**这一节不能省略。** 先肯定再谈问题，是客户愿意读下去的前提，也是执行方愿意拿去讲的前提。

标准 4–5 条，从这五个角度找：

1. **素材是否真实**（实拍 vs 图库）
2. **产能/规模是否看得见**（堆垛、装柜、产线）
3. **产品线是否够宽**（能否支撑 3 个月不重复）
4. **执行链路是否已通**（有没有持续更新过）
5. **是否出现过爆款**（如有，明确指出这是可复制的结构信号，不是运气）

每条必须用**具体画面或数字**支撑。写「素材质量不错」是空话，写「产线实拍占比高，装柜画面能直接证明出口体量」才是判断。

## 1.4 问题诊断表

**维度基准 10–12 个**，从下面清单按客户实际挑 10 个以上，不许少：

| 典型维度 | 检查什么 |
|---|---|
| ① 用户名（handle） | 是否与品牌关联，是否像英文单词 |
| ② 多平台身份统一 | 各平台名称/头像/简介是否一致 |
| ③ 头像质量 | 手机端 40px 下是否可辨识 |
| ④ Bio 与钩子 | 有无 who / make / cert / MOQ / contact 五要素 |
| ⑤ 内容信息层级 | 是「内部资料」还是「对外内容」（有无钩子/参数/结论） |
| ⑥ 关键词优化 | 口播 / 花字 / 文案 / 标签是否埋采购搜索词 |
| ⑦ 爆款复用 | 高播放那条的同结构续作有没有做 |
| ⑧ 系列化 | 内容有无「追更」理由，账号垂直度 |
| ⑨ CTA 与转化链路 | 视频结尾、主页按钮、私信入口 |
| ⑩ 参数证据 | 关键参数 / 认证 / 公差 / 交期 / MOQ 是否出现 |
| ⑪ 平台定位错位 | 是否沿用「发帖带链接跳官网」的思路 |
| ⑫ 账号环境与养号痕迹 | 新号痕迹、环境是否固化 |

表格列固定：`# | 维度 | 现状 | 问题本质 | 直接后果`

**「问题本质」要写机制，不写现象。**

| 坏写法（现象） | 好写法（机制） |
|---|---|
| 简介太简单 | 没有告诉买家做什么规格、什么认证、怎么联系，主页访问不转化 |
| 视频拍得不好看 | 前 2 秒是 Logo 与航拍，没有信息，完播率过不了推荐门槛 |
| 参数太少 | 买家最关心的公差与认证一次都没出现，无法作为采购依据转发给同事 |

## 1.5 核心矛盾（一句话）

**一句话，加粗引用块。** 公式：

> **你们已经有「{真实优势}」，但做成了「{现状错位}」，而不是「{买家真正要看的东西}」；而且 {第二层机制问题}。**

示例（虚构）：
> **你们已经有「真工厂」的画面，但拍成了「给同行看的库存记录」，而不是「给买家看的采购依据」；而且所有内容都在等平台发善心推荐，没有一条主动把流量引向询盘。**

这一句是整份方案的支点——后面每一章都要能呼应它。写完回头检查：第三章每个平台的打法，是否在解决这个矛盾。

---

## 1.6 目标客户画像

表格，列固定：`优先级 | 市场 | 典型买家 | 决策角色 | 在哪个平台活跃 | 内容语言`

- 优先级用 ★★★ / ★★ / ★
- **市场给具体国家**。不写「中东」，写「中东（沙特 / 阿联酋 / 卡塔尔 / 阿曼）」
- 「在哪个平台活跃」必须给强度（极高 / 高 / 中）
- 多平台时**按平台分层**：某个平台是俄语区主战场，就单独起一小节（例：A. 俄语区与中亚：VK 主战场）
- 结尾必须给「首期主攻：{X} + {Y}」+ 三条理由

### 变体：买家是个人消费者（C 端 / 收藏者）时怎么改

上表的「决策角色」默认对位采购经理、技术总监、老板。产品卖给个人时，这套尺子量出来的是错的。

| B2B 采购 | C 端收藏者 / 玩家 |
|---|---|
| 决策角色：采购 / 技术 / 老板 | 决策角色：**自己**，一个人拍板 |
| 驱动因素：认证、公差、交期、MOQ、价格 | 驱动因素：**情绪、身份认同、怕后悔、社群评价** |
| 参考来源：规格书、第三方检测报告 | 参考来源：**其他买家的实拍、评论区、开箱视频** |
| 决策周期：周–月 | 决策周期：**看到的那几分钟** |
| 内容给什么：参数 + 证据 | 内容给什么：**使用那一刻的画面 + 别人也在用** |

此时 1.7 不要写「采购核对清单」，改写成三个问题：

1. **他在担心什么**（会不会不合适、会不会坏、会不会后悔）
2. **圈子里怎么评价这件事**（有没有人晒过、口碑如何）
3. **买了之后我会不会显得很懂**（身份收益）

一句话提醒：**C 端买家不读参数，但会为了「别人晒的那张图」下单 —— 内容要拍的是那张图，不是参数表。**

如果客户同时做 C 端和小 B（如零售店、主题店），在画像表里分两行写清，并在结尾明确「首期主攻 C 端」还是「先做 B 端示范」——两个一起用力，等于都没有。

## 1.7 决策关键要素（内容的靶心）

买家询盘前心里在核对的 **6–10 个问题**，逐条编号。

**每条都要能被翻译成一条视频选题。** 翻译不出来的删掉。

结尾加一句机制说明：「每条视频至少要回答其中 1 个」。

制造业常见要素：材质/牌号、规格与公差、表面处理、性能实测值、认证、模具与开模周期、MOQ、交期、包装与装柜、售后与替换政策。

---

## 1.8 差异化定位（UVP）

**一句话，不超过 25 字**，格式：

`{能力} + {可验证的数字或证据} + {对谁}`

示例格式：`{N} 个断面 + {N} 天开模 + {指标}实测 ≥ {值}，给 {目标市场}{客户类型}的 {品类}厂`

下面补 3 条支撑证据，每条都必须可验证（第三方报告 / 客户可看到的现场 / 公开可查的资质）。

---

## 1.9 一句话诊断结论

与 1.5 核心矛盾呼应，但更可执行。三要素：

`现状` + `最大机会` + `首期该先做什么`

## 诊断章自查

- [ ] 1.2 每个平台的每条数据都能追溯到截图/客户告知/公开核验
- [ ] 1.2 有「数据放在一起读」的四条解读
- [ ] C 端账号已算「粉丝转化率 / 关注数 / 收藏÷播放」三个数
- [ ] 1.3 有 3–5 条，且每条都有具体画面或数字
- [ ] 1.4 ≥ 10 个维度，每条「问题本质」写的是机制不是现象
- [ ] 1.5 是一句话，且第三章能呼应上
- [ ] 1.6 市场落到具体国家，平台活跃给了强度，结尾有首期主攻
- [ ] 买家是个人消费者时，已改用「C 端收藏者」变体，1.7 写的是「他在担心什么」而不是采购清单
- [ ] 1.7 每条决策要素都能对应一条内容选题
- [ ] 1.8 UVP ≤ 25 字，附 3 条可验证证据
- [ ] 全章没有编造数字，缺失处标「截图未包含」或「需客户确认」
