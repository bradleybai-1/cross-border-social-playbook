# 配套视频脚本方案（第二份交付物）

> **主方案回答「做什么」，脚本方案回答「怎么拍」。** 只给主方案，客户拿到手会卡在分镜上。
> 这一份是独立文档，不是主方案的第四章。

---

## 一、什么时候出

| 情况 | 出不出 |
|---|---|
| 默认 | **出。** 两份一起交，这是标准交付物 |
| 用户明说「只要方案，不要脚本」 | 不出，但主方案第四章的首批清单必须写全钩子与拍摄要点 |
| 用户明说「只要脚本」 | 只出脚本，但脚本里的选题必须能追溯到主方案的 2.2 内容板块 |
| 纯图文平台为主（如 Pinterest、LinkedIn 长文） | 改出「图文帖子文案」，仍用本文件的第三、五节 |

**判断口径**：客户执行团队里有没有人能自己写分镜？几乎没有。所以默认出。

---

## 一之二、写多少条：默认 12 条，只写能拍的

**规则：首批脚本默认写 12 条，只写「素材已就位、当月内能拍完」的条目。**

不是把主方案首批清单的条数全部展开。清单里那些需要提前埋线、等第三方素材、等用户返图的，**不展开分镜，单独列一张「待素材条目」简表**。

理由三条：

1. **写了的拍不了，等于没写** —— 一条「需提前 30 天埋线」的脚本占两页篇幅，客户看完只会觉得执行不了
2. **12 条已经够一个月的产能** —— 每周 3–4 条，12 条刚好撑满首月，写多了是纸面繁荣
3. **待素材条目单独列反而更受重视** —— 摆成一张「缺什么、等多久」的表，客户才会真的去准备；混在 12 条正文里，会被当成又一条常规内容

### 待素材条目简表的格式

在正文之后单列一节，不写分镜，只写四列：

| # | 选题 | 为什么现在拍不了 | 缺什么 / 等多久 | 何时补拍 |
|:-:|---|---|---|---|
| {N} | | 时间型 / 外部型 / 用户型 | {具体缺什么} | 第 {X} 周 / 待客户提供后 |

**这条简表本身就交付物的一部分**——它告诉客户「你的首月内容里，有两条卡在你手上」。

## 二、文档骨架（七节，照抄不改）

```
# {客户全称} · {英文名}

## 配套视频脚本方案（首期 · {N} 条主线内容）

### —— {产品线简述} · {平台列表} · {YYYY-MM-DD}

> 每条视频脚本固定 9 项（见第三节）：标题行（含定位）/ 目标 / 平台时长 / 钩子 / 逐秒分镜表 / 标题文案（含标签）/ CTA / 中文对照 / 拍摄要点
> 通用铁律：① 前 2 秒结果前置 ② 满屏英文字幕 ③ 无中文字样与水印 ④ 结尾必有询盘钩子 ⑤ 各平台版本时长与开头不同

## 一、脚本总览（{N} 条）
  表格：# / 主题 / 主平台 / 时长 / 类型 / 爆款潜力

## 二、逐条视频脚本（含逐秒分镜）
  每条一个三级标题，字段固定，见第三节

## 三、图文帖子文案（图卡轮播 / 长图文 / 群组帖母版）

## 四、一条素材 → {N} 种剪法（复用规则）+ 发布 Checklist

## 五、DM / 评论回复话术（与主方案附录 C 保持一致）

## 六、拍摄日清单（{X} 个半天拍完首月素材）

## 七、待素材条目（不展开分镜，只列缺什么）
  {N} 条，四列：选题 / 为什么拍不了 / 缺什么等多久 / 何时补拍
```

**文件命名**：`{客户简称}_配套视频脚本方案_{YYYYMMDD}.md`
**禁止**在文件名里用 `+` —— URL 里会被解析成空格，客户端打不开。用下划线或「与」。

## 三、逐条脚本的固定字段

每条必须齐这 9 项，少一项都算不合格：

| 字段 | 要求 |
|---|---|
| **标题行** | `### 脚本 #{N}　{主题}（{一句话定位}）` |
| **目标** | 这条要达成什么，一句话。不能写「增加曝光」 |
| **平台 / 时长** | 每个平台给一个时长，不同平台时长必须不同 |
| **钩子（前 2 秒）** | 一个具体动作或一个具体数字 + 对应的英文字幕原文 |
| **逐秒分镜表** | 见下方写法规则 |
| **标题文案** | 每个平台一版，不能一稿多发 |
| **CTA** | 评论区关键词 + 私信动作，必须具体 |
| **中文对照** | 一行说清这条在讲什么，给中方执行团队看 |
| **拍摄要点** | 最容易拍砸的那一处，写出来 |

### 逐秒分镜表

| 时间 | 画面 | 字幕（英文，烧字） | 口播 / 音效 |
|---|---|---|---|
| 0:00–0:02 | | | |

**七条写法规则**

1. **时间精确到秒**（0:00–0:02），累计必须等于标注的总时长
2. **前 2 秒必须是动作、结果或数字** —— 禁止 Logo 开场、禁止航拍开场、禁止「大家好」
3. **字幕全程烧字**，因为绝大多数人静音刷。字幕就是唯一的口播
4. **字幕里必须出现关键规格或结论**，且用大写强调（`MEASURED EVERY BATCH`、`NOT {竞品材料}`）
5. **口播写短句**，一句一个信息。买家可能不是英语母语
6. **音效写具体的现场声**（卡尺「嗒」、气动「嗤」、机械「咔」）—— 现场声是专业感来源，BGM 只是底色
7. **每条写一个「拍摄要点」**，指出这一条最容易拍砸的地方

### 结构模板（15–34 秒通用）

| 时间 | 用途 | 硬要求 |
|---|---|---|
| 0:00–0:02 | 钩子 | 动作或数字，必须让人停住手指 |
| 0:02–0:08 | 建立场景 | 谁在做、做什么、为什么重要 |
| 0:08–0:20 | 给证据 | 参数 / 实测 / 对比，**必须出现数字** |
| 0:20–0:28 | 给结论 | 一句话说清这说明什么 |
| 0:28–0:34 | 给动作 | 一个 CTA，只给一个 |

> 长视频版（45–70 秒）在「给证据」段扩写，并补一段工程师出镜讲解；开头钩子必须换掉，不能与短视频版同帧。

### 轮播 / 图文脚本的字段模板

视频用上面 9 个字段。**轮播没有时长和分镜，字段不同，别硬套**：

| 字段 | 要求 |
|---|---|
| **标题行** | `### 脚本 #{N}　{主题}（{一句话定位}）` |
| **目标** | 这条要达成什么（收藏？转发？B 端询盘？） |
| **形式** | 轮播 {N} 图，尺寸 1:1 或 4:5 |
| **逐图说明表** | 见下 |
| **标题文案** | 平台 caption，前 40 字符含关键词 |
| **CTA** | 一个动作 |
| **中文对照** | 一行说清在讲什么 |
| **拍摄要点** | 最容易做砸的那一处（如：必须实景、必须同机位） |

逐图说明表：

| 图 | 画面 | 图上文字 |
|:-:|---|---|
| 1 | 封面：给结论 | 大字 |
| 2–{N-1} | 逐张给证据 | 一句一个证据 |
| {N} | CTA | 下一步动作 |

**三条铁律**：
1. **首图必须给结论**，不能是产品全景配品牌名——轮播的打开率全靠首图
2. **末图必须是 CTA**，中间不要插 CTA
3. **图上文字和 caption 不能重复**，图上给结论，caption 给理由和钩子

## 四、脚本总览表

在正文之前先给一张总表，让人 30 秒看完这 12 条是什么：

| # | 主题 | 主平台 | 时长 | 类型 | 爆款潜力 |
|---|---|---|---|---|---|
| 1 | | | 25s | 门面 | ⭐⭐ |
| 2 | | | 18s | 工艺 ASMR | ⭐⭐⭐⭐⭐ |

- **类型**列不许全写「产品展示」。至少覆盖：门面 / 工艺 ASMR / 知识教学 / 能力证明 / 案例 / 出口 / 信任
- **爆款潜力**用 ⭐–⭐⭐⭐⭐⭐，且**必须至少有一条 ⭐⭐⭐⭐⭐** —— 全片没有一个爆款候选，首月不会有突破
- **总览表只列展开分镜的条目**（默认 12 条）；待素材条目单列简表，不进这张表
- 爆款候选优先选：**高信息密度的过程画面**（开模瞬间、装配一镜到底、对比实验、点亮瞬间）

## 五、一条素材 → N 种剪法

这是脚本方案里最能省成本的一节。**一源多剪，但严禁一稿多发。**

| 素材类型 | 短视频版（15–34s） | 长视频 / 信息流版（45–70s） | 图文版 |
|---|---|---|---|
| 过程 / 工艺 | 去口播，纯现场声 + 字幕 | 加工程师讲解 + 结尾 CTA 卡 | 关键帧做 6 图轮播 |
| 能力 / 规模 | 快切 + 数字字幕 | 加「能力清单」字幕段落 | 参数对比表图卡 |
| 教学 / 诊断 | 钩子问题 + 3 点结论 | 完整版 + 配套长图文 | 分步图卡 |
| 质量 / 信任 | 证书 / 报告特写快切 | 加流程说明 | 报告样例轮播（数据打码） |
| 通用要求 | 满屏字幕、无中文、无外链、结尾钩子 | 首帧封面标题、结尾 CTA、链接放评论 | 首图带标题文字 |

#### 单平台（如只有 Instagram）怎么处理

**关键认知：三条通道不是「同一素材剪三版」，是三个层级 + 一条独立素材线。** 把它们并列会做错。

| 通道 | 层级 | 素材从哪来 | 判断标准 |
|---|---|---|---|
| **Reels** | 拉新 | 产品拍摄（主战场） | 静音能不能看懂 |
| **轮播** | 收藏 | 产品拍摄（抽帧 + 图卡） | 值不值得存下来 |
| **Stories** | 信任 | **独立素材线**：打包、发货、仓库、返图、日常 | 像不像真在做生意 |

- Reels 与轮播可以同源（抽帧做图卡），但**开头不能同帧**
- **Stories 几乎不是从产品拍摄里来的** —— 它要的是「后台画面」。指望从产品片里剪 Stories，会剪出一堆产品广告，反而降低信任
- Stories 每天 1–3 条，每周至少一次互动贴纸（投票 / 提问）。它 24 小时消失，但它是算法判定账号活跃度的直接依据

> 做单平台方案时，Stories 要单独列一张「日常素材清单」，不能挂在视频脚本后面当附注。

### 发布 Checklist（每条都要过）

- [ ] 前 2 秒有硬钩子
- [ ] 全片目标语字幕，无中文字样、无水印
- [ ] 标题前 3 个词含关键词或型号
- [ ] 标签分层混搭，**与上一条的组合不同**
- [ ] 发布后 30 分钟内置顶一条带钩子的自评
- [ ] 发布后 60 分钟内回复所有评论
- [ ] 多平台时另存一份并换开头，不同时同稿发

## 六、图文帖子文案母版

### 6.1 图卡轮播（5–6 张）

固定节奏：**封面给结论 → 中间逐条给证据 → 末图给 CTA**。

```
1. 封面：{核心能力或结论}（大字 + 产品全景）
2. {参数 1}
3. {参数 2}
4. {参数 3}
5. {覆盖范围 / 应用行业}
6. CTA：{下一步动作} + 联系方式
```

配文（英文）三段式：**痛点一句 → 我们的数据 2–3 行（必须带数字）→ CTA 一句**。

### 6.2 长图文（母版 · 换第一段即可复用）

> **{年份} 选 {品类} 供应商真正重要的 {N} 件事**
> 1. **{维度 1}** — {一句话，带数字}
> 2. …
> 最后一行为 CTA：把{图纸/样品/需求}发我，用你自己的{零件/项目}回答这 {N} 条。

这类长图文的传播逻辑是「值得转给同事」，不是「好看」。

### 6.3 行业群 / 社区经验贴（严禁硬广）

```
Title: {N} 个我报价前必做的检查

1. {检查项}（{为什么}）
2. …

Happy to share the full checklist — comment or DM.
```

**不带价格、不带链接、不放联系方式在首段** —— 带了就是广告，会被踢，还可能关联主页风险。

## 七、拍摄日清单

按**场地**排，不按选题排。换场地的时间成本远大于换选题。

| 时段 | 场地 | 覆盖脚本编号 | 需准备的实物 |
|---|---|---|---|
| 09:00–10:30 | | #{1,3,5} | |
| 10:30–12:00 | | #{2,4} | |

**排之前先按「素材就绪度」分三组，不分组会排出一张拍不完的表：**

| 组 | 含义 | 处理 |
|---|---|---|
| **必拍** | 素材已就位、当天能拍 | 优先排进拍摄日 |
| **加分** | 能拍，但缺了不影响方案成立 | 时间够就拍，不够延后 |
| **待素材** | 当天拍不了，缺前置条件 | **单独标注缺什么、要等多久** |

**「待素材」常见三类，遇到必须写清等待周期**：

| 类型 | 典型情况 | 写法 |
|---|---|---|
| **时间型** | 需要放置/使用一段时间才有对比（积灰、老化、磨损） | 标注「需提前 {N} 天埋线」并给出埋线日期 |
| **外部型** | 需要第三方场地、合作门店、客户现场 | 标注「需客户提供素材，无则不发」 |
| **用户型** | 需要真实用户返图、评价 | 标注「需先征集 {N} 周，第 {X} 周才发」 |

**每个半天再拆「必拍」与「加分」两组**，时间不够先保证必拍。清单尾部加「拍摄后处理」：

- [ ] 素材按「{过程 / 参数 / 人物 / 场景 / 信任}」分类归档
- [ ] 每条正片剪出各平台版本
- [ ] 统一加目标语字幕，去除所有中文与水印
- [ ] 封面帧手动选定 + 加标题大字

## 八、红线

1. **认证、参数、产能必须由客户确认后写入**。未持有的证书严禁出现在画面或文案里，哪怕是「示意图」
2. **未确认项要在脚本条目内部就地标注，不能只写在文末红线里。** 用 🔴 + 一句「{X} 需客户确认后才能发布」直接标在那条脚本下面 —— 执行的人看的是条目，不是文档末尾
3. **不摆拍做不到的效果** —— 测不出来就不拍
4. **字幕与口播里的数字必须与主方案附录 E 参数卡一致**，两份文档不能出现两个数
5. **示例与模板里不得出现任何真实客户信息**（本 skill 本身的开源示例更要注意）
6. **不承诺效果** —— 不写「这条必爆」，只写「爆款潜力 ⭐⭐⭐⭐⭐」并说明依据（画面信息密度 / 争议性 / 情绪强度）

## 九、自查清单

- [ ] **条数口径对得上**：脚本条数（默认 12）= 主方案首批清单条数 − 待素材条数；三处编号能互相指认
- [ ] 待素材条目已单列简表，写清「为什么拍不了 / 缺什么 / 等多久 / 何时补拍」
- [ ] 总览表里至少一条 ⭐⭐⭐⭐⭐，且说明了依据
- [ ] 每条**视频**脚本 9 个字段齐全，无空项（轮播走第三节的轮播字段模板，不套这 9 项）
- [ ] 每条分镜表时间累计 = 标注时长
- [ ] 每条前 2 秒是动作 / 结果 / 数字，**没有一条是 Logo 或航拍开场**
- [ ] 每条字幕里至少有一个具体数字或具体结论
- [ ] 每个平台的标题文案都单独写过，不是同一句复制
- [ ] 每条只有一个 CTA
- [ ] 每条都有「拍摄要点」，且写的是最容易拍砸的那一处
- [ ] 轮播条目用的是轮播字段模板（不是硬套视频 9 字段），首图给结论、末图给 CTA
- [ ] 拍摄日清单已按「必拍 / 加分 / 待素材」分组，待素材项写清了缺什么、等多久
- [ ] 未确认项已就地标注在脚本条目内，不是只写在文末
- [ ] 第四节剪法表覆盖了客户在用的全部平台；单平台时 Stories 有独立素材清单
- [ ] 全文数字与主方案附录 E 参数卡无冲突
- [ ] 没有任何未确认的认证 / 参数被写进去
